# v0.9.0 合并发布说明

本次交付包含原子入库与分类治理，以及 Impeccable 审查发现的八项界面修复。基于已经上线的 v0.8.0 整合，保留 D101 标签打印、目录树、product v2、批量接口和请求追踪。

## 入库与分类治理

- 批量读取上下文，一次事务提交商品草稿、分类扩展和所有实物；结果丢失时用原幂等键查询回执或重试。
- 分类规范、别名和历史例外版本化。新增规范、越界入库和独立目录修改通过明确的确认卡片授权。
- product v2 保质期字段保留；旧批量接口同样检查分类放置限制；目录属性升级也需要对应批准。
- 两份 Skill 源码位于 `plugin/skills/`。用 `python3 scripts/package-intake-skills.py` 生成两个可导入 zip，并作为 GitHub Release 附件发布。发布附件不等于用户宿主已导入。
- 新增迁移为 `008_intake_policy.sql`；已发布迁移保持原字节。发布控制器在数据库迁移前备份，失败按既有恢复流程处理。

原始自动化和服务端探针证据保留于 [入库验收记录](intake/acceptance.md)。其测试数字属于早期候选，不能替代合并后的 CI。

## Impeccable 修复（按原报告顺序）

1. 入库编辑与核对分为两步，摘要获得焦点；返回编辑保留草稿，确认前没有写入。
2. MCP 接入初始和动态安全区、容器尺寸；滚动区、底部导航、抽屉共享边界，部分通知保留已有约束。
3. 修正辅助文字、占位文字、链接及选中位置的对比度。
4. 手机同款实物显示编号尾号、开封记录、余量及到期信息；未知状态保持未知。
5. 压缩手机首屏控制区，排序移入筛选，保留原有操作。
6. 商品选择支持名称、品牌、规格、型号和条码搜索。
7. 统一工作台、目录、搜索和详情标题层级，保留主线目录树。
8. 手机抽屉关闭按钮的触控区域至少 44×44 px。

本地 Impeccable 复审评分由 12/20 升为 16/20；抽样 axe 无违规，detector 返回空列表。复审基于浏览器模拟及隔离 MCP 宿主。相关回归保存在 `tests/browser/impeccable.spec.ts`。

## 发布验证与验收边界

合并后执行类型检查、Web/MCP 构建、完整领域/MCP/OAuth测试、Chromium 与 WebKit 回归、合成数据库备份恢复、真实容器迁移及恢复测试。准确结果以对应提交的 GitHub Actions 与 Release 记录为准；只有 Release 部署任务成功、生产健康端点的版本和提交匹配时才算上线完成。

真实手机语音耗时、跨表述分类语义稳定性、Skill 宿主加载，以及真实 ChatGPT 手机 composer/键盘/旋转/安全区，仍需实机验收。自动化和生产健康检查不能替代这些结论。验证使用合成库存，不用正式库存做写入实验。
