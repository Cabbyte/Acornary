# 松仓前端融合方案

日期：2026-10-14。状态：已批准并完成本地实现；以下保留设计决策，交付范围及验证边界见 [v0.10.0 发布说明](release-v0.10.0.md)。

## 1. 推荐方向

继续使用现有 Ant Design 6、React、统一工作台与编辑抽屉，将新稿的家庭储藏视觉、按商品组织物品、关注事项和单件档案引入现有应用。

主线是：先知道有哪些商品，再辨认具体哪一件，最后记录它发生的变化。位置限定当前查看范围；商品分组帮助理解数量；真正的编辑、消耗、移动始终落到明确的实物。

新稿是视觉与体验参考，原型中的内存数据、日期算法与默认值不成为实现依据。

## 2. 已核对的基础

- `ui/theme.tsx`：统一 Ant Design Provider，已有陶土主色、浅色方案和手机 44px 控件。
- `ui/workbench.tsx`、`ui/inventory-layout.tsx`：可折叠导航、可调整位置树、按可用宽度切换详情、UUID 选择和列表状态恢复。
- `ui/forms.tsx`：统一 ActionDrawer，已有入库、消耗、整件用完、开封、移动、资料编辑、纠错与笔记；保留草稿、原始数量字符串、版本与幂等提交。
- `contracts/web.ts`：已有按商品聚合，包括件数、位置数、开封情况、可汇总余量；百分比不相加。
- `domain/index.ts`：已有按家庭时区推导提醒日期的逻辑；单件接口已使用它。
- `service.ts` 的 `get_history`：目标可省略，已支持家庭范围的历史；当前前端主要提供对象历史页面。
- Web 快照目前没有家庭时区；增加首页日期提醒时需要补齐共享读取模型，不能默认所有家庭都是上海时区。
- `ui/viewport.ts` 与 `ui/layout.css`：已有宿主安全区、容器高度、屏幕键盘与动态视口适配。

## 3. 冲突与取舍

| 冲突                             | 推荐决定                                                            | 依据                                                                     |
| -------------------------------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| Ant Design 默认外观与新稿视觉    | 保留组件行为，用主题 token 和业务布局实现暖纸色、陶土色与清楚的层次 | 现有表单、焦点、错误反馈和响应式行为可以继续复用                         |
| 新稿独立“存放位置”与现有位置树   | 位置继续属于“我的物品”的范围筛选                                    | 选房间后仍需搜索、分组和操作同一批物品，独立页面会分散上下文             |
| 新稿每件一张大挂牌与现有密集表格 | 默认商品摘要，展开后是紧凑的单件条目；另保留“不分组”明细            | 同时支持了解家中储备和处理大量实物                                       |
| 详情永久占位与现有按宽度展开     | 选中后出现，可关闭；空间不足时用抽屉或全页                          | 主列表需要足够阅读宽度，不能为了三栏而挤压内容                           |
| 新稿“历史”与现有仅对象历史       | 增加“动态”主入口，单件档案保留对象时间线                            | 回答“最近改了什么”和“这件发生过什么”两个不同问题                         |
| 新稿手机底栏混入“入库”按钮       | 底栏只放我的物品、商品目录、动态、设置；添加放在当前页面            | 导航改变页面，添加开启操作，含义应稳定                                   |
| 新稿全局“消耗”与现有对象操作     | 消耗以前置选择具体实物为主，商品层入口先选择实例                    | 六瓶同款不能只减商品数量，也不能自动替用户选瓶                           |
| 原型自动深色与现有浅色约定       | 第一版完成统一浅色；token 可扩展，但不新增自动深色行为              | 保持当前明确约定，避免颜色、宿主与状态对比度同时扩大验证范围             |
| “状态”指代不一致                 | 分开库存状态、可用性、开封、状况                                    | 当前列表 unknown 依据可用性，新稿 unknown 依据库存状态，不能共用模糊标签 |
| 表单简单但默认事实过多           | 保留简洁层次；日期、开封、余量和精度默认未记录，件数为明确可见的 1  | 少填字段不应导致虚构事实；当前日期类型的默认 ESTIMATED 也一并去掉        |

## 4. 信息架构与页面

桌面导航：我的物品、商品目录、动态；设置固定在下方。品牌与家庭切换放在导航顶部，减少与内容区重复的顶栏。导航收起后家庭切换仍保留可见入口。

手机：顶部保留品牌和家庭切换，底部四个入口与桌面一致。添加物品在物品页标题区，商品页可提供“添加这款”。

### 我的物品

页面顺序：标题及结果总数 → 搜索、添加与视图工具 → 当前范围和关注事项 → 结果。

- 默认“按商品”，另外支持“按位置”“按日期”“不分组”。手机用一个分组选择器收纳，不铺满多排按钮。
- 查询维度各自明确：位置回答在哪；分组回答如何组织结果；筛选回答只看哪些；排序回答先看谁。
- 位置树留在工作台内部，可调整宽度。窄屏变成位置选择抽屉；“家 / 厨房 / 冰箱”与“包含下级”始终显示在结果区。
- 搜索覆盖名称、规格、品牌、位置、编号与笔记。先搜索完整快照，再分组和分页；搜索词命中笔记时给出短摘要提示。
- 当前结果与全家庭数量分开表达，例如“当前范围 8 种商品 · 23 件实物”，不会把当前结果误称为家庭总库存。
- 位置计数维持其所在位置及下级的总数，并明确标为总数；关注事项计数随当前范围、搜索和其他筛选变化。

### 商品分组与单件

商品摘要示例（仅示意）：

> 光明全脂牛奶 1L　6 件 · 2 个位置 · 1 件需留意　展开

展开后显示轻量单件条目：物品名称/实例名、位置、最有用的日期或余量、可区分的开封/借出状态。完整 UUID 与 revision 不常驻；同款难以区分时使用稳定短编号和已知差异，不能按当前位置重新编号。

- 默认展示商品摘要，用户展开的组会记住状态。只有一件时直接提供进入档案的入口。
- 搜索和关注筛选优先显露匹配实物，避免为了看到一个临期物品再额外展开多层；显示模式不会悄悄覆盖用户长期偏好。
- 物品卡不使用装饰打孔占空间；保留浅暖底色、细边线、选中时陶土色强调。
- 所有单件条目保留商品识别线索，商品组很长时保持组标题可识别，不能只剩一串相同的“冷藏上层”。
- 食品突出开封、日期和余量；设备突出型号、位置、借出/维护；衣物突出尺码、颜色和清洗等已知信息。根据已记录属性决定摘要，完整详情仍能记录更多资料。
- “未记录”保持可查询，摘要不为每件物品列出所有空字段。无适用日期信息的电钻、衣物不默认承担到期提醒。

分页：按商品模式按商品组分页，明确“每页 20 种”；很大的单组展开后再分页展示单件。按位置、按日期和不分组仍以实物分页，明确“每页 20 件”；跨页的组提示续页。件数与组数不能共用同一模糊分页标签。

批量操作：所有选择最终是实物 ID。列表全选只选当前可见的单件；“选择本组匹配的 N 件”必须是另一个写明范围的操作。分组、筛选及翻页不会丢失选择，隐藏选择须提示“已选 5 件，其中 3 件不在当前结果”，并能查看或清除。切换家庭清空选择。确认页列出实际对象和目标位置；超过现有 100 件限制时明确要求分批，不能静默截断。

### 需要留意

仅在物品页保留一组入口，取消新稿侧栏与顶部的重复提醒。

- 日期已过：提醒日期早于家庭当地今天。
- 近期日期：从今天到未来 14 天，包含今天；排除已经过去的日期。
- 余量不足 30%：只有已记录百分比，或已记录同单位净含量基准可计算比例时进入。没有基准时显示绝对余量，不从名称中的“1L”猜测。
- 不在手边：借出、清洗、维护、运输等可用性，列表中显示具体原因。

日期的行内文案忠于其含义：“使用期限已过”“超过最佳食用期”“计划日期已过”分开表达，不能统称过期。开封后期限与已记录日期取较早者，并能看到依据。列表、提醒计数、分组与详情共用一套日期推导；家庭时区跨日时更新。未知日期不混入到期数量。

多个关注条件同时启用时按“满足任一关注条件”组合，UI 明示；与搜索、位置和其他属性筛选取交集。每个入口计数基于当前范围及其他筛选，暂不受这组关注开关自身影响。

### 单件档案

内容顺序：名称及规格、完整位置 → 关键事实与适用操作 → 详细资料 → 笔记 → 最近动态。

- 余量已知时突出显示“约 420 mL”，估计标识与数值相邻。仅在百分比或已知有效基准下画进度，数值缺失不画假进度；按 SKU 净含量计算时注明“相对标称净含量”。
- 相关操作直接可见：记录消耗、移动、编辑；开封、纠错、标签打印等按适用性安排到次级入口，已有能力保持可达。
- 记录消耗统一入口中区分“用掉一部分”和“整件用完”，默认不把整件用完置为隐含选择。余量未知时允许整件用完，按量操作提供“记录余量”直接入口。
- 笔记在档案可读，新增和编辑继续使用统一草稿/编辑容器。关闭详情、筛选、调整窗口不能无声清空正在编辑的文字。
- 最近动态用人话描述变更前后，提供完整历史链接；完整 ID、revision 与原始字段放在“技术信息”折叠区。
- 不默认选择第一件。用户点击一件后才打开档案；过滤导致该件不在结果中时，明确提示“当前查看的物品不在筛选结果中”，保留用户主动查看的对象。切换家庭或对象失效则清除。

### 添加与编辑

主按钮继续叫“添加物品”，旁边菜单“添加位置”。已有商品与新商品在同一流程中选择，保留目录规范检查与必要确认。

第一层：选商品、件数、位置。日期、开封、余量和笔记按需展开；有输入的分区保持展开。件数默认 1，位置只在用户已选具体位置时预填；全家庭视图不指定位置；其余事实保持未知。

提交前保留简明核对，展示实际将创建的件数、商品、位置及填写的事实。选错商品或触发分类确认时返回原草稿，不重头填写。日期类型初始为空，纯日期不经过 UTC 转换。

所有编辑沿用 ActionDrawer：桌面抽屉，手机全屏；固定可达的提交区。同一个草稿实例不随断点改变而重建。

### 商品目录与动态

商品目录管理“是什么”，我的物品管理“手上有哪些”。分类树继续复用现有组件；商品详情展示共享资料、当前实物数及“查看这些物品”“添加这款”。编辑共享资料时说明影响同款，单件操作不会隐式修改商品。

动态展示家庭近期操作，使用现有家庭范围 get_history；支持进入相关物品和查看完整操作。按 operation_id 归并同一操作的多条事件，展开时读取该操作完整记录，避免分页把一次入库看成几次操作。操作人只显示服务返回且能可靠解析的信息，不虚构姓名。日期、目标筛选仅在服务具备正确完整查询时提供，不能只筛当前加载页。

## 5. 视觉与组件约束

- 页面暖纸色以新稿 `#F6F0E6` 为参考，内容面 `#FFFCF6`，正文暖深色 `#2B2420`；主色沿用 `#AB5F40`。具体值须以真实文本对比度验收。
- 蜂蜜色用于小面积品牌和余量提示；警告、危险、选中分别承担明确含义。
- 品牌和少量页标题使用宋体气质；列表、表单、数字继续系统无衬线。使用系统/本地资源，不依赖 Google Fonts 或新增插件网络权限。
- 控件和面板遵守现有 8/12px 圆角与间距体系；弱化大白卡片套娃、粗阴影和重复分割。
- 原生 Ant Design Button、Table、Tree、Splitter、Descriptions、Timeline、Drawer、Form 继续负责各自行为；新增的是业务视图组件，不另建通用控件库。
- 选择/展开/抽屉用短状态过渡，支持减少动态效果；不增加进场表演。
- 全局主题覆盖账号、设置和授权等页面，核心信息结构调整集中在工作台、目录、档案与动态。

## 6. 响应式原则

布局依据内容可用宽度，不仅按屏幕宽度硬套三栏。物品列表是需要优先保留宽度的区域。

- 宽屏：导航、位置树、列表；选中后若仍能为列表保留约 640px，再并排显示详情。
- 普通桌面：导航可折叠；详情用抽屉，位置树在空间不足时转抽屉。
- 手机：单列摘要和单件条目，位置抽屉，全页档案；切回列表恢复搜索、分组、展开和滚动。
- 主操作触控目标至少 44px；输入文字至少 16px；长名称、路径、屏幕键盘和横竖屏切换不遮挡操作。
- Web、ChatGPT 和 Codex 共享同一布局逻辑，继续处理真实宿主 safe area、容器高度及视口变化。

## 7. 工程拆分与边界

1. 主题与布局：`ui/theme.tsx`、`ui/layout.css`、`ui/inventory-layout.tsx`。
2. 工作台业务组件：在 `ui/workbench.tsx` 拆出商品组、单件条目、关注筛选和档案，控制主文件复杂度。
3. 共享展示推导：统一 `lib/workbench.ts`、`lib/browse.ts` 与 `lib/presentation.ts` 的搜索和状态含义。固定顺序：家庭/范围 → 搜索/过滤 → 分组/排序 → 分页。
4. 日期读取：为 Web 与 MCP 共享快照补充家庭时区；将提醒日期规则提取为可共享的纯函数，服务端与前端复用。旧缓存缺时区时暂不推导相对到期标签，仍可展示已记录绝对日期并等待新快照，不猜时区。同步更新插件解析结构，避免新字段被丢弃。
5. 行为接线：在 `ui/forms.tsx`、`pages.tsx`、`workspace.tsx` 复用现有操作，调整入口和信息层次，新增动态路由及所需历史展示字段。

本方案预计无需数据库迁移或更改库存写入协议；有小范围只读数据类型/快照扩展。保留版本冲突、准确请求重试、写入成功但刷新失败只重读、离线只读、目录审批以及宿主选择上下文。不能把单件选择变成商品级授权。

## 8. 实施顺序与验收

建议在一个候选版本里分四步完成并统一验收：

1. 主题、导航、响应式骨架；用同一份数据对照当前版和候选版。
2. 分组、提醒、状态/日期推导与选择；先确认计数和实例身份，再润色显示。
3. 单件档案、添加/消耗/移动/笔记、目录及动态闭环。
4. 回归、真实内容与宿主验收，最后决定发布。

代表性验收场景：

- 同款六瓶分处两个位置，开封和日期不同：能识别并只消耗所选那瓶，商品分组不会合并实物身份。
- 上百件混合物品、长型号、多层收纳、一个商品很多实例：浏览、搜索、分页、跨页选择和返回位置稳定。
- 设备和衣物没有到期数据：摘要没有无意义的到期占位，仍可查看或补充适用资料。
- 未知余量、不同单位和估计值：不自动补满、不相加百分比、不把包装名称解析为事实。
- 纯日期、开封后期限、家庭时区跨日和不同日期含义：列表、关注计数及详情一致。
- 无匹配、空库存、离线、只读、失效登录、版本冲突和提交后刷新失败：有明确去路，原草稿可恢复。
- 360/390/768/1024/1440/1920px 下无关键信息或操作被裁切；键盘与宿主安全区变化不丢草稿；真实手机与真实插件宿主另行确认。
- 键盘操作能展开商品、选择实物、关闭详情并返回原焦点；对比度、标签和朗读名称合格。

先做有意义的展示推导与操作回归，再完成仓库要求的类型、构建和浏览器检查；不把测试通过称为真机或生产发布完成。

## 9. 当前方案中的明确建议

默认商品摘要、展开单件；位置留在物品工作台；增加动态入口；提醒只出现一次；保留统一抽屉和现有写入链路；第一版统一浅色。

这些是本轮推荐，尚未作为实现或发布指令执行。
