# 产品原则与用语

## 本轮要改变的使用体验

日常模式面对拿着一件物品、刚买回一袋东西、或正在找东西的家庭成员。首屏让他找到具体对象、看到足够判断的事实、直接开始任务。管理模式面对整理目录、调整收纳、核对多件资料和追查变化的人；让结构与影响范围可见。任何成员都可切换模式，写权限仍取决于当前服务端身份。

界面首先展示“这是什么、在哪、已知余量、需要注意什么”，再展示完整资料。不能为了让首页显得整齐，把未知余量写为零、把未知状态写为可用，或丢掉同款实物的独立身份。

## 冻结的语义规则

| 概念                | 主界面用语                                           | 必须保留的边界                                     |
| ------------------- | ---------------------------------------------------- | -------------------------------------------------- |
| SKU                 | 商品 / 商品资料；数量为“款”                          | 新建商品资料不会增加库存；同名不等于同款           |
| Item                | 物品 / 这一件；数量为“件”                            | 全 ID 参与命令；同款不共享余量、位置、笔记和事件   |
| GROUP               | 商品分类                                             | 只在目录树中归类，不能成为位置                     |
| parent Item         | 存放位置 / 容器                                      | 只有有效且可容纳的 Item 可选；根位置写“未指定位置” |
| opening             | 开封情况                                             | 未记录、未开封、已开封分别显示                     |
| lifecycle           | 在库 / 已用完 / 已处置等具体状态                     | 未记录不推断在库；VOID 为记录作废，与物品用完不同  |
| contents            | 剩余量；估计 / 实测 / 依据未记录                     | 十进制字符串；单位明确；百分比不能跨件相加         |
| expiry USE_BY       | 使用期限（原包装）                                   | 日期超过时写“已过使用期限”，不用于其他日期类型     |
| expiry BEST_BEFORE  | 最佳食用期                                           | 写“已过最佳食用期”；不宣称一定不可食用             |
| expiry ESTIMATED    | 计划日期（估计）                                     | 食品可说明“计划吃完”，不升级为厂家期限             |
| expiry 无 date_kind | 日期（类型未记录）                                   | 不能归入“过期”；按记录日期展示，不补类型           |
| deadline            | 保修截止 / 维护日期 / 归还日期 / 续期日期 / 补货日期 | 沿用真实 kind；完成与改日期是不同操作              |
| correction          | 纠正记录                                             | 需要原因；不能伪装通用撤销，也不篡改历史           |
| redacted            | 内容已隐藏                                           | 不等于未记录；明确查看权限与披露流程               |

日期的 absolute 值、类型、依据、来源始终保留。家庭时区缺失或非法时显示绝对日期及“时区未确定”，禁用相对日期分组，不用设备时区代填。

短标签只用于区分同名实物：已知位置、开封信息优先；仍相同则显示稳定标签尾号。尾号不能成为命令身份；碰撞时显示更长尾号或完整 ID。屏幕阅读器可读尾号以辨认对象，完整 UUID 默认留在“记录信息”。

## 决策规则

1. 一次任务一个明确主动作。字段填写区即核对区；只要范围和最终结果足够明确，无须再弹一层无信息的“确定吗”。整件结束、处置、作废和目录审批仍有专门影响确认。
2. 日常列表默认逐件紧凑行，搜索可切到“商品”；商品汇总只提供“查看这些实物”和“再添这款”。不提供商品级“减 1 件”。
3. 用户输入优先保留。切模式、转屏、键盘开关和恢复网络不能重置任务。已发送请求以原参数和原幂等键恢复。
4. 服务端结果是成功的证据。拿到回执但列表刷新失败时显示“已保存，最新列表尚未读到”，只能重读；不能再次创建或消耗。
5. 高级能力由 feature、实体 capability、权限、运行时传输、在线与可恢复存储共同决定。模式不参与鉴权。
6. 现有功能通过管理详情、目录、设置或受控外部入口保持可达；不能因日常页面简化而删除。
7. 手机管理模式仍可完成任务；宽表转为逐件摘要和列配置，不能要求手机用户横向拖动整个页面。

## 视觉方向

延续松仓的暖纸与系统字体，建立同一家族的两种使用密度。日常用陶土强调与宽松阅读；管理用灰蓝强调与对齐列。避免用颜色替代“日常 / 管理”文字。统一 danger / warning / success / info 及焦点样式，不随模式改含义。
