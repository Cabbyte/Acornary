# 无障碍与多端验收规则

目标为 WCAG 2.2 AA 相关要求及本产品更严格的触摸尺寸。不能用一次 axe 通过宣称完整合规；需键盘、屏幕阅读器、触摸、缩放和真实宿主验证。

## 可操作性

| 区域         | 键盘/焦点行为                                                | 验收方式                                             |
| ------------ | ------------------------------------------------------------ | ---------------------------------------------------- |
| Shell        | 第一项跳转主内容；nav/main/header清晰；当前页aria-current    | 从地址栏Tab到主操作，不穿过无意义重复导航            |
| 模式切换     | 有可读文字，radio语义；改变模式后有简短状态播报              | 不依赖颜色判断模式；返回键恢复原路由                 |
| 搜索         | label恒定；IME不发中间查询；Enter查询；Escape先关候选        | 屏幕阅读器播报结果数/错误，不每次按键朗读全列表      |
| Item行       | 名称链接、复选框、更多是独立控件；Enter/Space遵循原生语义    | 不嵌套button/link；朗读名称+位置+必要尾号            |
| 管理表格     | caption、th/scope、可用排序aria-sort；选中范围朗读           | 不为只读表格硬套电子表格键盘模型；所有动作可Tab到达  |
| 目录/位置树  | Arrow上下移动、右展开/左收起、Home/End；选中与焦点分开       | 层级/展开状态可读；搜索结果提供完整路径              |
| Sheet        | 标题/描述关联；打开到标题或首个必要字段；背景inert；焦点trap | Escape遵守任务守卫；关闭回原控件，不存在则回列表标题 |
| 选择器子步骤 | 保存父表单，返回回原字段；最多一层主要模态                   | 嵌套菜单先关闭自身，Escape不连续关闭两层             |
| 错误/成功    | 字段错误aria-describedby；首错聚焦；业务错误role=alert       | 成功结果以polite播报，重大失败不只Toast              |
| 未决请求     | 可达恢复条、明确原请求动作、无自动重发                       | 键盘离开后仍可找回；超时不永久困在模态               |

快捷键可选：/ 聚焦搜索，输入框/contenteditable内不拦截；不覆盖系统/浏览器常用组合。核心任务不依赖快捷键或拖拽。拖拽整理若后续增加，必须有“移动到…”等价入口。

## 字体、颜色与视口

正文/占位/辅助文字按正常文本至少4.5:1；大字至少3:1。本稿候选色以文本4.5和必要控件/焦点3为计算阈值；状态同时有文字和图形。低对比分隔线仅用于装饰，不作为输入控件唯一边界。参见 [W3C 文本对比度](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum)、[非文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast)。

手机主要触控目标至少44×44 CSS px，输入文字至少16px；桌面36px控件在粗指针环境升为44。浏览器200%文字缩放、400%页面缩放、320px有效宽度不得丢关键内容。长中文/英文型号允许换行；标签和错误不限单行。

焦点环2px、偏移2px，须与临近背景对比足够且不被sticky页头/提交栏遮住。滚动定位留scroll-padding；软键盘打开后焦点字段、错误和提交按钮可到达。iframe内焦点不能跑到父文档。[W3C 焦点不被遮挡](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum)

prefers-reduced-motion关闭位移和循环闪烁；保存状态不依赖动画。高对比/forced-colors下用系统边框和文字保留选中、焦点、错误。纯日期输入不按设备时区转换；读屏名称包含日期类型。

## 覆盖环境

- Web：Chromium、WebKit、Firefox；至少360 / 390 / 768 / 1024 / 1440 / 1920宽；记录浏览器版本和设备像素比。
- 真实手机：Safari/iOS软键盘、VoiceOver，大字体和安全区；Android Chrome/TalkBack与软键盘。不是用桌面触摸模拟替代。
- MCP：真实ChatGPT/Codex可用宿主分别验证。覆盖320/390/768内容宽、动态resize、安全区、键盘、无localStorage、widgetState失败/重挂载、读写scope变化。
- 打印：支持桌面Web的真实D101独立验证，纸张输出与设备回执分别记录；扫码相机权限、识别和跨家庭链接分开验证。

Tailwind v4官方基础浏览器范围为Chrome111、Safari16.4、Firefox128起；Phase 2需核实实际宿主引擎，不因宿主品牌就假定满足。若低于要求，停止该环境切换并登记，不暗中变更已选技术栈。[官方浏览器兼容说明](https://tailwindcss.com/docs/compatibility)

## 验收产物

每个主要流程记录：设备/宿主/版本、宽高/键盘状态、输入方式、起点、完成动作、focus返回点、错误/修复、证据路径。axe Critical/Serious必须为0，其余问题登记负责人和处置；人工主流程任何无法继续/不可达按钮均阻止该面板验收。截图、自动化、人工和真实设备结果在[矩阵](acceptance-matrix.md)分列，不相互代替。

本轮只做候选Token数值计算和规格定义，没有执行axe、屏幕阅读器、真实浏览器或宿主无障碍验收。计算结果见[token-contrast](token-contrast.md)。
