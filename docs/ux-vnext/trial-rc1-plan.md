# Trial RC1 — 完整产品隔离试用版执行方案

状态：待执行方案。日期：2026-11-09。当前核对基线：`codex/frontend-vnext` / `8a9589b`，工作树在本方案写入前干净。

本轮承接用户对 Pages RC1 的整体正向反馈，目标是连续试用。该反馈不自动转换为 29 个页面逐项批准或 Phase 2 工程验收通过。RC6 组件批准及已有页面批准历史继续保留。

## 1. 目标、交付名称与边界

交付 **Trial RC1：完整产品隔离试用版**。用户从“我的物品”开始，通过应用自己的导航完成日常、管理、设置任务，跨页看到一致结果；可以关闭后继续试用，并在当前页面提交修改意见。

本轮属于 Phase 2 的完整体验候选，不是 Phase 3 接线或发布。不增加项目阶段，不改领域模型，不改正式 Web/MCP 入口，不移除 Ant Design，不接 Cloudflare 运行时，不部署或推送。

全部库存、账号、权限、审批、设备状态继续使用隔离样例。正式 React 页面和共享应用逻辑可复用；fixture、故障注入、示例执行器及反馈服务继续限于开发装配层。

**回归测试继续暂停。**本轮仅执行下文列出的类型、构建、静态边界与有限人工检查；未执行的工程验收保持未通过。

## 2. 三个入口与默认体验

| 入口 | 地址 | 用途 |
| --- | --- | --- |
| 完整试用版 | `http://127.0.0.1:6008/#/items` | 日常连续体验，打开即进入示例家庭 |
| 页面/组件审阅 | `http://127.0.0.1:6007/` | 单页场景、尺寸切换、反馈追踪 |
| Storybook | `http://127.0.0.1:6006/` | 原子组件与边界状态审阅 |

6008 使用显式独立 Vite 配置，只绑定本机，禁止业务代理与 Service Worker。原入口及原反馈记录保持可用。三个入口引用相同的正式组件与页面；试用版不加载整个组件目录或全部 stories。

默认已进入示例账号及“梧桐之家”，首次使用不强制走模拟登录。默认日常模式、苔绿与石板蓝，仅是试用默认值；四套配色和两种模式全部保留。后续以当前 URL 优先，其次账号/家庭范围内的模式偏好，最后默认值。

页面保留一个轻量“试用版 · 示例数据”标识及“提意见”入口，不再展示工作台的大段说明、尺寸选择和场景控件。场景/时钟/角色切换及重置放在“设置 → 试用工具”。正式产品默认配色不因这次默认值而自动冻结。

## 3. 页面范围与连续任务

完整接入现有 29 页：日常 16 页、管理 6 页、设置 7 页。保留已确认的排版、文案密度、图标操作、四套配色和 RC6 尺度；仅调整连续产品体验需要的 Shell、导航与状态表达。

| 范围 | 本轮必须能连续体验的行为 |
| --- | --- |
| 浏览与档案 | 我的物品 → 搜索 → 商品 → 单件档案；返回保留查询、分页、滚动与适当焦点 |
| 入库与使用 | 已有/新商品入库 → 独立 Item → 列表/档案；使用/移动 → 数量/位置/动态一致更新 |
| 开封与日期 | 修改开封或日期 → 档案更新 → 需要留意按同一家庭时区和试用时钟重新计算 |
| 笔记与附件 | 单件/商品范围明确；保存、隐藏、关联、移除后的数量和内容在相关页面一致 |
| 扫码与标签 | 识别示例 QR/条码 → 指向已存在对象或明确候选；标签预览与打印任务共享目标身份 |
| 目录与位置 | GROUP/SKU 与物理 Item 两棵树独立；目录资料影响商品摘要，物理移动影响路径及子容器显示 |
| 管理操作 | 编辑、模板、策略、拆包、作废/恢复、批量及纠错 → 相关读取结果和同次操作历史一致 |
| 账号与设置 | 切换示例家庭/角色 → 导航中的家庭、数据范围、操作可用性、草稿与选择一起变化 |

不支持的命令、关联或能力保持明确受限分支。新 SKU 类型/能力的原子入库缺口、100 件上限及禁止任意全结果选择等约束不变。不能因试用而将不支持的功能模拟为可接线能力。

## 4. 导航、响应式与上下文

继续使用 TanStack Router，试用版采用 hash 路由以支持独立本地入口与刷新；路由命名沿用现有 `/items`、`/products/:id`、`/tasks/...`、`/daily/...`、`/manage/...`、`/settings/...`。外层工作台参数不进入产品路由。

- 桌面保留侧栏；手机日常底栏为物品/留意/动态/设置，管理底栏为物品/目录/位置/动态/设置。添加仍是明确的任务入口。
- 模式切换位于桌面侧栏底部、手机顶部；设置共享且保留模式上下文。
- 单件档案切管理时进入同一 Item 的精确编辑；精确编辑切日常时回同一档案。商品页对应目录中的同一 SKU。没有对应页面时进入目标模式首页，并保留原路径作为返回上下文。
- 搜索、分页、合法筛选和对象定位由 URL 表达；未保存字段不放入 URL。家庭访问先校验当前示例成员范围，不能借深链接绕过。
- 切换模式和配色不重挂载任务，不产生库存事件。浏览器前进、后退和深链接纳入同一导航规则。
- 6007 的稳定审阅链接继续兼容；正式生产 QR 和历史 URL 不在本轮改写。试用扫码只解析可映射到隔离数据的身份，不请求生产对象。

试用版随真实窗口/内容宽度布局，不保留审阅 iframe 的 760/680px 固定高度。明确一个主内容滚动区；侧栏、底部导航与任务面板处理安全区、键盘和动态视口高度。继续保持 360px 下正常换行、44px 触摸目标、手机输入至少 16px，不缩放整页来伪装响应式。

## 5. 统一隔离数据与查询投影

建立一个版本化 TrialWorld，取代各 Journey 内互不相通的世界状态。它只存在于试用适配层，按现有契约保留事实；页面依然接收受控 View Model 和意图回调。

| 数据 | 统一规则 |
| --- | --- |
| 账号、家庭、成员 | 两个隔离家庭；示例所有者/成员/只读身份；数据和任务按账号/家庭隔离 |
| 目录与模板 | SKU/GROUP、类型能力、模板版本和覆盖值共用；未知字段保持原样，不因不能编辑而删除 |
| 实物与位置 | 完整 UUID、revision、容器关系和有效性共用；位置不能借用商品分类 |
| 数量与日期 | decimal string、单位、精度、未知状态、日期类型/来源/依据/时区共用 |
| 笔记、附件、历史 | 按真实对象范围关联；每次操作统一 operation ID，避免重复事件或每页各自编造结果 |
| 打印与恢复任务 | 任务目标固定到明确 Item；记录发送、反馈、人工确认以及未决状态 |

商品摘要、列表、位置树、需要留意和动态从同一世界读取并派生，不分别保存显示用副本。可复用的纯投影规则放在共享应用层；试用数据生成、执行及故障处理留在 review/trial。

执行器复用或遵循既有 operation 名称、Zod schema 和可移植纯校验，不建立前端专属库存协议，不重写一个完整后端。缺少可靠能力映射时限制该执行分支并登记。

查询接口继续传递分页/筛选/排序和覆盖范围，返回当前页及明确统计语义；数据在本地也不意味着页面可以假设全量或无限选择。写入成功只在统一存储提交完成后发布；相关读取一起失效/更新。

试用时钟统一从现有 `2026-11-07` 样例基准开始，在试用工具内可见并可显式调整。页面的日期判断与历史使用同一时钟和家庭时区。调整试用时钟不伪造用户的日期事实或库存事件。

## 6. 持久化、刷新和多标签

使用试用专属 IndexedDB 保存世界、草稿、冻结请求与回执。建议数据库名 `acornary-trial-v1`，记录含 schemaVersion、数据集 ID、账号、家庭、任务 ID 和会话代次。通过存储适配器访问；正式组件不直接读写浏览器存储。

- 正常关闭/重开、刷新后继续使用同一隔离世界和已保存草稿；浏览器主动清理数据不在持久性承诺内。
- 数据集、草稿、原请求和回执使用事务及版本检查，防止“世界已修改，但回执没保存”后重复执行。
- 多标签写入先读取持久层最新版本并核对 revision；过时视图进入冲突，禁止覆盖旧快照。通知另一标签重新读取，不静默合并用户输入。
- 版本不兼容时保留旧存储，明确要求重置或迁移方案，不能静默清空。
- 模式和配色存储失败可退化为当前会话；任务持久化失败则禁止提交，保留当前输入并说明原因。
- 存储不可用时允许读取初始示例、导航与临时编辑，明确提示刷新不保留；不能显示虚假的保存成功。
- 不读取、迁移或覆盖正式生产草稿，也不自动导入 6007 历史审阅快照。

“重置试用数据”仅重置 TrialWorld 及其草稿、未决请求、附件和设备样例，先展示影响并确认；不能清除用户已提交的修改意见或旧审阅数据。未决任务必须明确列出，不能被普通“清理读取缓存”顺带删除。

## 7. 共享任务生命周期与作用域切换

抽取并复用既有纯逻辑，建立应用根部持有的共享任务会话。其状态与视图分离，页面离开只改变展示位置。生产旧控制器继续使用原绑定；本轮不迁移真实用户任务。

每个任务保存：账号/家庭/数据集作用域、目标 UUID、操作 schema、草稿、字段原值和期望 revision、审批摘要、冻结请求和稳定键、任务状态、回执、返回位置。审批/执行/读取和存储通过可替换适配接口提供。

| 状态 | 导航和恢复规则 |
| --- | --- |
| 草稿 | 先保存；切页/切模式保留；保存失败时允许重试或明确丢弃，不静默离开 |
| 校验/核对 | 字段错误就地显示；影响对象和范围明确；重复确认不能并发创建请求 |
| 审批 | 显式示例审批结果；修改目标或参数后原审批不继续适用；无能力时保持受限 |
| 提交中 | 拦截应用返回、关闭面板、切模式、切家庭；强制刷新/关闭后的原尝试恢复为待核对，不自动重发 |
| 成功 | 以适配器传入的实际示例回执更新状态；返回原上下文，不生成第二次提交 |
| 版本冲突 | 保留输入，显示原值/当前值/拟修改值；重新读取核对；明确失败的旧尝试终结后才可建立新尝试 |
| 结果不确定 | 固定原键和原参数；允许保留任务后离开；全局恢复入口只显示当前作用域的未决任务 |
| 离线/无权限 | 保留可读范围与草稿，禁止写入；权限失效不能靠切模式解除 |
| 身份变化 | 丢弃旧读取响应，隔离选择、缓存和任务；旧任务只在其原账号/家庭下可恢复 |

试用执行器的“结果不确定”场景应真正模拟“变更已提交但回执未送达”，再次恢复查询同一回执，证明前端不会重复建立 Item。与“提交前失败”分别提供。

家庭切换时：提交中先阻止；草稿保存后可切；未决任务保留在原家庭并明确提示返回核对。切换完成同时更新当前家庭、所有页面查询、选择与操作可用性，不再出现设置显示 B 家庭而列表仍是 A 家庭的情况。重新登录/切账号同理，且不向新账号显示旧任务内容。

真实身份鉴权、审批挑战、原子事务与幂等恢复仍由 Phase 3 服务端接线和验收证明；本轮的纯逻辑与隔离演练不能替代它们。

## 8. 登录、附件和设备的试用边界

- 默认登录状态为示例身份。登录、退出、恢复、邀请、OAuth 和 MCP 授权提供明确的示例状态与操作，不调用真实提供商、不创建真实凭据、不要求用户提供真实密码/验证码。
- 只读角色应同时限制页面按钮和本地命令适配器；直接打开编辑 URL 也不能执行写入。它只是前端行为演练，不宣称服务端授权验证通过。
- 扫码提供示例 QR、商品条码和手动输入；不主动请求摄像头权限。多件库存需明确选择，不能以商品条码代替实物身份。
- 附件默认使用内置样例文件，展示本地关联、预览和移除；不上传到外部服务。附件与笔记都由统一世界管理，重置范围明确。
- 标签可以生成与当前 Item 对应的预览；打印发送、设备反馈、纸张确认由模拟适配器驱动，显式标为示例设备。不调用真实蓝牙/打印机，不自动重打未知结果。
- 冷启动离线、真实相机/蓝牙/打印及真实 MCP 宿主不在本轮可用性承诺内。离线情景是可控故障注入；本地开发服务停止后不能承诺页面仍能打开。

## 9. 逐页反馈、版本和复审

试用顶部保留安静且可发现的“提意见”按钮，桌面与手机均可达，打开后不重置原任务。弹层任务中的意见记录对应页面、任务种类和当前步骤；关闭反馈恢复原焦点。

复用现有本地反馈服务，6008 也写入 `.local/ui-review-feedback/`，继续限制本机同源。复用稳定 page ID，增加向后兼容的来源和任务上下文元数据：Trial RC1、路由、模式、配色、实际宽度、示例场景、任务阶段及数据集版本。元数据不附带完整世界、附件内容、密码或笔记正文。

提交失败保留意见，重试沿用同一提交 ID；没有保存到本地文件前不能显示成功。现有“已处理/待处理”记录和批准历史保持可见；浏览或提交意见不等于批准。

6007、6006 与试用页始终引用同一正式源码。组件修改后更新版本和受影响页面清单，保留逐组件复审能力。纯静态构建包没有本地反馈服务时，应明确显示不可提交，并支持保留/导出意见文本，不能冒充已保存到仓库。

## 10. 工程组织与实施顺序

保留现有工程、技术栈与依赖版本。建议新增：


## 11. 检查范围与试用任务

新增 `dev:ui-trial` / `build:ui-trial`，分别启动 6008 和输出 `output/ui-trial`。类型检查纳入候选应用与试用配置。

允许执行：

- `pnpm exec tsc -p apps/web/tsconfig.json`
- `pnpm build:ui-trial`、`pnpm build:ui-preview`、`pnpm build:storybook`
- `pnpm check:ui-boundaries`、`pnpm check:ui-tokens`、`pnpm check:ui-catalog`
