# RC1 布局、层级与文案审查

2026-11-06。范围为当前 70 个公开组件和 5 个组合场景；本轮只形成修正建议，不修改 UI 或组件批准状态。完整业务页面尚未装配。

## 方法和证据边界

- 两份独立源码审查：布局与信息层级、文案与动作密度；覆盖 70 个组件、8 个组件 demo 模块和 5 个组合实现。
- 浏览器读取全部 5 个组合场景的正常态，额外查看操作面板和 390px 表单；结合用户提供的三张截图。
- 浏览器量测来自实际 DOM，不按截图像素反推 CSS 尺寸。不把当前有限浏览器检查称为 591 状态穷举或多浏览器验收。
- 没有运行测试、构建、性能基准或自动设计检测器；回归继续暂停。没有业务、设备调用，临时检查页已关闭，视口覆盖已恢复。

## 共性结论

1. 宽度增大时，领域内容仍沿用纵向排列；加宽外框没有增加信息横向组织。
2. 身份、日期、输入等组件默认展示接近完整详情，组合时再次添加说明和状态，缺少摘要与详情的展示层级。
3. 物品名有实际 CSS 覆盖问题：名称字重声明为 500，但后续 `.vn-fact-link { font: inherit }` 覆盖它。浏览器确认可点击名称为 14px / 400。
4. 审阅说明和产品文案混在内容区；规则、测试边界、原始技术信息占用日常任务空间。
5. Shell、内容装配和 Storybook 存在多层内边距；Shell 固定高度又引入内部滚动。

四套配色和已定正文尺度可保留。整改应集中在布局、默认信息层级、标题样式及文案，而不是统一缩小字号和触摸区域。

## 建议的默认设计规则

### 宽度与间距

- 按组件实际可用宽度切换布局，不以横屏/竖屏或设备名称判断。
- 侧栏、树表并列等断点与现有Token意图统一：侧栏从1024、树区按主体可用宽度960起考虑并列；不足时使用紧凑入口。
- 表单内容足够宽时两列，短日期/单位不无限伸展；阅读文字与短编辑仍保留合理最大宽度。
- 页面边距只设置一层：桌面24、窄屏16；组间24、字段间16、关联事实4–8。保留触屏44px目标和16px输入字号。
- 仅选中时显示批量动作；避免无选择也展示家庭UUID、0/100和多个禁用按钮。

### 物品层级

- 日常列表名称建议16px/600、正文主色；管理密集表格可14px/600。修复继承覆盖，常态去掉下划线，hover/focus保留可发现反馈。
- 宽屏默认采用：名称与规格｜位置｜余量｜真实日期类型与日期｜主要动作和更多。
- 手机重排为名称/状态、关键事实两到三行；长名称、错误和未知值允许增高。
- 完整UUID保留在身份详情、复制与操作核对中；选择和所有回调仍使用完整UUID。同名多件必须依位置、日期及可区分身份信息澄清，不用名称替代身份。
- 来源、依据与技术字段保留访问入口；不把它们每次全部展开在日常行里。

### 文案和图标

| 当前常驻文字 | 建议 |
| --- | --- |
| 这一件物品的名称 | 物品名称；若影响范围需澄清，在任务标题/核对范围表达一次 |
| 记录使用 | 使用；保留短文字，纯图标不够明确 |
| 标记数量未记录 | 数量字段内的“未记录”状态入口；保留明确操作含义 |
| 日期用途 + 最佳食用期 + 日期口径 + 下方同样日期预览 | 单次显示“日期类型”和日期；输入旁不重复整块事实预览 |
| 小数位按输入保留；未记录与0不同 | 普通态帮助中按需查看；验证行为及实际“未记录”状态保留 |
| 清除日期后，仍保留日期用途和依据 | 从正常态删除这句教学文字；真实数据行为保持 |
| 来源：生命周期事实 | 日常摘要移到来源详情；原始技术分类在管理/详情中可查 |
| 未设置筛选条件 | 默认省略；有条件时展示筛选数量与标签 |
| 切换展示方式，保留正在编辑的内容 | 移入帮助；有未决任务或阻断时显示对应原因 |

- 图标适合关闭、清空、展开/收起、复制、日历、更多、成熟的编辑入口；统一Lucide，提供可读名称、焦点提示及触屏可达的解释。
- 使用、入库、移动、审批、危险确认、未知结果恢复保留短动词或“图标+短文字”。不把所有按钮强行变成图标。
- 图标视觉尺寸与触摸区域分开；缩短文字不缩小点击区域。不能只依赖鼠标hover解释关键动作。
- “核对原请求结果”建议缩为“核对原请求”；不改成可能被理解为重新提交的“重试”。

### 信息层级

1. 默认显示：名称、关键事实、当前影响范围、必要状态、主动作。
2. 按需显示：完整编号、来源依据、版本、普通帮助、技术回执、审阅说明。
3. 正常态删除：重复标签、重复预览、已经由界面表达的规则、无过滤/无选择的冗余提示。
4. 始终保留：未知不等于零、估计性质、真实日期类型、身份歧义、权限/缓存范围、审批与危险影响、冲突和结果未知恢复。

预览环境统一保留一条“预览 · 示例数据”标识；详细测试边界和点击日志移出产品画布，收进审阅说明。长文案压力测试场景继续保留，不能靠缩短fixture逃避长文本适配。

## 下一轮建议顺序与验收目标

1. 统一摘要/详情与帮助文案规则，修复ItemIdentity标题层级。
2. 重排ItemRow/ItemCard与表格单元格，合并搜索/筛选工具区。
3. 重排QuantityInput/DateFactField及表单分区；统一页面边距和容器断点。
4. 将规则应用到恢复、导航、附件、历史、扫码和打印相关组件。
5. 回到五个组合场景复核；保持现有审阅机制、四套配色和业务流程。

下一轮设计验证目标（尚未实现或验收）：1440×900独立预览中，普通短内容列表首屏显示约5–6件；普通表单的必要字段与主按钮在一屏或少量滚动内到达。长文本、错误、审批和冲突可按需要增高，不裁剪事实来达成数字。390px保留单列主任务和触摸尺度，不出现水平滚动。宽屏优先减少无意义纵向堆叠，而不是无限加宽所有控件。

本轮没有冻结上述候选新默认值，也没有把用户对展示机制满意记成组件视觉批准。
