## 实际接入

`apps/web/src/app-vnext/index.ts` 是无 review/fixture/Ant 依赖的候选出口。它提供：

- `scope.ts`：环境、账号、家庭、客户端、数据集的稳定命名空间，以及单独的会话代次比较。
- `routing.ts`：页面注册、受限应用路径、模式解析、查询参数更新和返回上下文类型。`PageJourney` 的路由注册、模式选择及参数更新已实际消费这些纯函数。历史对象、滚动/焦点恢复和 Shell 装配仍在 review 层。
- `query.ts`：复用既有 API 查询能力裁剪函数；提供协议查询端口、带作用域/代次的缓存键和迟到读取拒绝函数。`PageJourney` 实际消费带覆盖率的本地快照分页投影；离线部分缓存的总数仍为未知。**没有实现生产查询服务、缓存容器、分页拉取、筛选/排序接线或查询失效执行**；`writeInvalidations` 仅表达既有失效目标。
- `operation-session.ts` 与 `operation-context.tsx`：根 registry 持有 `OperationSession`。相同作用域、代次和任务标识重新打开时取得同一个对象。页面卸载/模式切换不会销毁任务执行 Promise。会话记录保存原始输入、当前输入、目标、期望版本、审批引用、冻结尝试和结果；存储/执行端口由装配注入。
- `platform.ts`：持久存储、命令执行/恢复、导航和可选扫码/打印接口。真实 Web/MCP/设备适配器未实现，不能把这些接口声明理解为能力已接通。

连续试用的 `Trial` 根在 keyed 页面之外持有 `FixtureApplicationProvider`。逐页审阅在没有已有 Provider 时，由 `PageJourney` 添加局部根 Provider。P03 的四种任务——已有商品入库、新商品入库、记录使用、移动——已实际使用新根会话；`TaskJourney` 的 React 状态只保留打开状态、选择器搜索和冲突选择等视图信息，持久输入、请求和回执由会话管理。它不直接调用本地世界执行器、不持有提交定时器、不直接读写浏览器存储。

## 持久化与恢复不变量

1. 每个任务的保存操作串行。提交前再次保存完整冻结参数并等待适配器成功确认；该保存失败不执行发送。传给执行器的尝试深度冻结，页面修改无法改写原请求。
2. 网络不确定、同键异参冲突和回执保存失败保留原尝试。提交接口不接受以新尝试替换不确定请求，恢复入口使用原尝试。回执保存的异常与服务端明确拒绝分别分类；仅列明的领域拒绝码允许判定 rejected，HTTP 408/429 和不含明确领域拒绝码的代理 4xx 均保守保留原请求；即使浏览器存储异常带数字 `code`，也不能把已执行成功的请求解释为可新建请求的验证错误。
3. 版本冲突保留输入和旧尝试，必须由重新读取后的事实、版本和明确选择调用 `reconcile`；不会自动采用新版本发送。开始下一样例使用当前读取的 revision，不延用上次提交前版本。
4. 存储失败保留内存输入并标记未可靠保存。`retain` 失败时阻止任务关闭和路由离开；未保存任务加入离开页面、家庭/角色变化的守卫。存储恢复后可以再次保留。
5. 每次执行、保存结果都校验代次。旧身份/家庭响应不写入新作用域；旧待定尝试仍留在原命名空间，再次回到该作用域可恢复原请求。正式 adapter 还需实现宿主自身的账号失效/回读保证，接口不代替这些保证。

`OperationStorage.save` 返回成功必须表示其承诺的可靠保存已经完成。当前 fixture 继续使用 Trial RC1 的 localStorage 日志和 IndexedDB 镜像策略；这只是隔离试用适配，不足以证明生产 Web/MCP 的持久性、跨标签并发或宿主回读要求。生产存储集成前必须独立评审这些语义。

## RC1 隔离任务兼容

P03 保留 `acornary-review-p03:*` 键和既有全局恢复入口。adapter 识别旧 RC1 的 `{ draft, request, state, reviewing, receipt }`，只在内存中转成候选记录，首次正常保存才写入新记录格式。旧请求的 key、冻结 draft、expectedRevision 和样例世界回执保持不变；原 key 缺失或格式不能安全恢复时保留旧记录并拒绝覆盖。

旧 RC1 请求原本不是实际 HTTP wire payload。转换时生成的 schema 合法 command 是**隔离试用的参数校验投影**，不代表找回了某次生产 wire 请求。执行仍使用本地世界执行器和它原有的幂等回执。adapter 从冻结 command 获取执行目标和操作，显式路由目标仅交叉核对，不以当前列表首项替换原对象。此转换不读取、迁移或重写 `src/lib/storage` 的正式草稿。
