# 页面内修改意见

2026-11-07。用户授权在审阅页面直接提交意见，替代逐条复制到聊天的方式。

## 使用

工作台（6007）、独立预览和 Storybook（6006）都有可展开的“修改意见”栏。填写后点击“提交意见”；看到“已保存到本地审阅记录”才表示落盘。可查看当前组件全部场景的历史，也可切到“全部页面意见”。评论不自动批准设计，不自动更改组件审阅状态。

每条记录包含完整原文、组件/页面 ID、名称、场景、外观、实际宽度、候选版本、提交时间和唯一编号。支持多条补充意见；当前不提供删除或覆盖原文。浏览器草稿按组件和场景隔离，切换与刷新后恢复；浏览器拒绝存储时明确提示，无法持久保存提交编号时不发送。

## 代理读取位置

在本工作树读取 `.local/ui-review-feedback/*.json`。这是用户实际提交的意见，不是 fixture；修改 UI 前读取并按组件/场景整理，保留原文。该目录被 `.local/` 规则排除 Git，不会随提交、构建或部署公开。需要备份时复制整个目录；不要在清理临时产物时删除。

6006 与 6007 的开发服务读写同一目录，各浏览器草稿仍独立。后续只需用户说“处理审阅意见”，代理即可读取上述文件，无需复制意见内容。没有聊天自动唤醒或后台代理订阅。

## 处理结果与复审

RC4 起，每条已处理意见下显示版本、处理状态及具体修改说明。原文保持不变，处理结果独立存于 `apps/web/review/feedback/resolutions.json`，以意见的唯一编号关联。该文件只包含处理摘要，不复制本地意见全文。

“已修改，待复审”表示实现已修改，仍需用户确认；不会自动将组件标为“已批准”。同一组件可继续补充意见，新意见会作为独立记录保存。全库候选与明确批准记录仍由 `apps/web/review/review-status.json` 管理。

首轮 18 条意见见 [RC4 报告](rc4-feedback-report.md)，新增 4 条意见见 [RC5 报告](rc5-feedback-report.md)。

## 工程边界与验证

仅隔离审阅开发配置注册 `/__review/feedback`；正式应用不导入服务或界面。接口只允许本机 Host，同源 JSON 提交，严格校验与长度限制。每条意见原子发布为独立文件，稳定编号重试去重，不覆盖既有记录。静态导出的审阅站没有写入服务，会显示不可用提示，不伪装成功。

实际检查：前端 TypeScript、隔离预览与 Storybook 构建、生产导入边界、diff 检查通过；人工确认输入、提交成功、刷新草稿恢复、两入口展示；定向检查磁盘落盘、6006/6007 共享读取、同编号重试、跨站拒绝。验证样例已移到 `.local/ui-review-feedback-verification/`，不混入用户意见。

完整回归、真实 MCP/设备和生产集成继续暂停。没有生产库存写入、推送或部署。
