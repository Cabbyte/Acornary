## PostgreSQL differential coverage

The real PostgreSQL snapshot suite now compares 13 read operations against the imported workerd DO: item, catalog node/policy, item/catalog/group/stock queries, references, notes, attachments, history and attribute templates. It also runs an ordered consume/rename/open/consume/clear-name sequence in both stores, comparing revisions, labels and attribute facts; verifies each store replays its original receipts; and compares stale-revision and excessive-consumption error codes with no native state mutation. The complete 14-test snapshot suite passes.

Two representation boundaries are explicit: PostgreSQL UTC text timestamps become ISO UTC while retaining fractional microseconds; legacy JSONB item aggregates may decode `projected_through_change_id` through a JavaScript Number and lose precision beyond 2^53. For that fixture the native string is checked against the original SQL bigint text, not the rounded legacy response. No unknown value is filled and no historical instant is recalculated. Other compared fields are strict. These bounded scenarios do not replace differential coverage of every possible command sequence.

## Failures found and addressed

- Live backup inspection found that an earlier manual backup suppressed that day's scheduled checkpoint. Scheduled runs now use a deterministic ID for the actual UTC trigger day, independently of manual runs; workerd tests verify manual/daily separation, duplicate delivery and the next day's checkpoint. The existing immutable restore/retention regression also passes.
- A browser CI focus assertion dispatched a repeated focus event without first leaving focus. The query library correctly deduplicated the event, making the assertion depend on initial browser focus. The test now models a hidden/visible focus cycle, retains the two-second assertion and passes five consecutive targeted runs; application behavior is unchanged.
- A second CI trace showed the passive page review superseding a synthetic fixture confirmation challenge. The fixture now reopens only the same proposal on `APPROVAL_EXPIRED` (bounded to three attempts), using the authenticated review/confirm flow; other conflicts still fail. Two consecutive visual-matrix runs pass.
- Deployment error `100328` rejected custom CPU configuration on Free. Removing that configuration allowed the complete application to deploy; it did not require removing any business feature.
- **Confirmed runtime CPU limit:** on 2026-11-05 at 09:18:36 UTC, the synthetic 25 MiB `PUT /api/attachments/upload/:upload_id` in the isolated full application returned HTTP 503 / Cloudflare 1102, Ray `a55ac511dfd7df08`. Wrangler tail reported `outcome: exceededCpu`, `cpuTime: 1109 ms`, and `Worker exceeded CPU time limit.` This is distinct from the earlier configuration error. The observed CPU duration is not the advertised Free limit: Cloudflare documents isolate flexibility before terminating consistently expensive invocations. See the [sanitized receipt](evidence/2026-11-05-free-cpu-limit.json) and [official CPU limits](https://developers.cloudflare.com/workers/platform/limits/#cpu-time). Free advertises 10 ms per HTTP request; Paid defaults to 30 seconds. This was the pre-optimization implementation. The replacement keeps the complete attachment contract and uses an upload-scoped coordinator, native SHA-256 and streaming R2 read-back verification. The failure remains recorded as historical evidence; it is no longer sufficient to conclude that the new implementation requires Paid.
- The real CIMD SDK supplies `redirect: 'error'`, which Workers Request rejects. The transport now constructs a manual-redirect Request and retains explicit redirect rejection. A full SDK/workerd regression covers this path; the actual Codex login subsequently succeeded.
- An independent HTTP authorization attempt later received HTTP 403 from the upstream Codex metadata document. No validation was bypassed and no metadata was fabricated. Successful CLI authorization and an occasional upstream fetch rejection are both recorded; ongoing client reliability must be monitored.
- Remote backup object staging encountered R2 error `10043`. The rehearsal tool now retries transient transport errors and checkpoints verified copies. The resumed rehearsal completed successfully. This was not a reported Free quota error.
- GitHub's Gradle distribution download returned HTTP 504 in one Android CI run; the failed job was retried. Browser and native checks in that run had passed.

## Release gates still requiring elapsed time or external clients

The preview is available for comparison; it is not permission to cut production over. ChatGPT host OAuth/UI, physical Android/Passkey/printing, controlled DNS rebinding, broad differential source-runtime sequences and a seven-day latency/error/usage observation remain separate acceptance items. The preview began observation on 2026-11-05; the upload coordinator release starts its seven-day observation on 2026-11-06 and cannot complete that window before 2026-11-13. No paid-plan upgrade has been made. Continue the preview on Free while measuring CPU errors, latency and quota use; recommend upgrading if the optimized application reaches an actual limit. Some successful non-upload Worker requests still exceed the advertised 10 ms CPU budget under Cloudflare isolate flexibility, so passing these scenarios does not guarantee reliability at higher or sustained load.

GitHub checks run automatically. Automatic preview deployment remains disabled until the `cloudflare-preview` Environment has a dedicated `CLOUDFLARE_API_TOKEN`; current releases use authenticated Wrangler OAuth. Do not store the local OAuth token as a CI secret. See the [release runbook](preview-release.md).

Formal cutover still requires a new write-fenced source snapshot and fresh production Cloudflare resources. Preview writes are discarded, never copied back into the existing production database.

Disposable remote resources are removed after their final reports are preserved; cleanup receipts are kept privately. The deployed preview and its pinned source backup remain.
