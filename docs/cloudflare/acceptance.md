## Failures found and addressed

- Deployment error `100328` rejected custom CPU configuration on Free. Removing that configuration allowed the complete application to deploy; it did not require removing any business feature.
- **Confirmed runtime CPU limit:** on 2026-11-05 at 09:18:36 UTC, the synthetic 25 MiB `PUT /api/attachments/upload/:upload_id` in the isolated full application returned HTTP 503 / Cloudflare 1102, Ray `a55ac511dfd7df08`. Wrangler tail reported `outcome: exceededCpu`, `cpuTime: 1109 ms`, and `Worker exceeded CPU time limit.` This is distinct from the earlier configuration error. The observed CPU duration is not the advertised Free limit: Cloudflare documents isolate flexibility before terminating consistently expensive invocations. See the [sanitized receipt](evidence/2026-11-05-free-cpu-limit.json) and [official CPU limits](https://developers.cloudflare.com/workers/platform/limits/#cpu-time). Free advertises 10 ms per HTTP request; Paid defaults to 30 seconds. Recommend Workers Paid, whose [base subscription starts at $5/month](https://developers.cloudflare.com/workers/platform/pricing/), with other usage charged separately. Do not reduce the attachment limit, remove checksum verification, or claim an occasional passing run proves reliable Free support.
- The real CIMD SDK supplies `redirect: 'error'`, which Workers Request rejects. The transport now constructs a manual-redirect Request and retains explicit redirect rejection. A full SDK/workerd regression covers this path; the actual Codex login subsequently succeeded.
- An independent HTTP authorization attempt later received HTTP 403 from the upstream Codex metadata document. No validation was bypassed and no metadata was fabricated. Successful CLI authorization and an occasional upstream fetch rejection are both recorded; ongoing client reliability must be monitored.
- Remote backup object staging encountered R2 error `10043`. The rehearsal tool now retries transient transport errors and checkpoints verified copies. The resumed rehearsal completed successfully. This was not a reported Free quota error.
- GitHub's Gradle distribution download returned HTTP 504 in one Android CI run; the failed job was retried. Browser and native checks in that run had passed.

## Release gates still requiring elapsed time or external clients

The preview is available for comparison; it is not permission to cut production over. ChatGPT host OAuth/UI, physical Android/Passkey/printing, controlled DNS rebinding, broad differential source-runtime sequences and a seven-day latency/error/usage observation remain separate acceptance items. The observation window starts 2026-11-05 and cannot finish before 2026-11-12. No paid-plan upgrade has been made. The confirmed CPU failure now supports recommending Workers Paid while retaining the complete upload contract.

GitHub checks run automatically. Automatic preview deployment remains disabled until the `cloudflare-preview` Environment has a dedicated `CLOUDFLARE_API_TOKEN`; current releases use authenticated Wrangler OAuth. Do not store the local OAuth token as a CI secret. See the [release runbook](preview-release.md).

Formal cutover still requires a new write-fenced source snapshot and fresh production Cloudflare resources. Preview writes are discarded, never copied back into the existing production database.

Disposable remote acceptance and restore Workers, D1 databases, R2 buckets and queues were removed after preserving reports. The deployed preview and its pinned source backup remain.
